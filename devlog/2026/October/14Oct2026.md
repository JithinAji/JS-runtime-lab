# Interpreter-Style Stepping & Call Stack State

Status: **Done**

## Motivation

Previously, step-by-step execution was implemented by taking slices of code lines (`lines.slice(0, currentStep)`) and evaluating them with `eval()`. This broke when executing multi-line functions, loops, or functions declared before their calls:

1. Slicing at `function one() {` caused syntax errors (`Unexpected end of input`).
2. Slicing treated execution as a flat vertical list of text lines rather than following the JavaScript engine's execution context lifecycle.

## What Was Done

1. **AST-Driven Step Generation (`acorn`)**:
   - Parses code into an AST and analyzes function declarations, parameters, local variables, and statements.
   - Function declarations are treated as hoisted declarations and skipped at the top level and inside nested scopes until invoked.
   - Calling functions steps into their bodies and returns back to the caller once completed.
2. **Call Stack Tracking**:
   - Maintains execution context frames with formal arguments (e.g. `add(10, 20)`).
   - Captures local variables and parameters while respecting the Temporal Dead Zone (`<uninitialized>`).
   - Captures return values upon executing `return` statements.
3. **UI Call Stack Panel**:
   - Added a Call Stack visual panel in `src/index.html` and `src/style.css`.
   - Displays active stack frames from top of the stack to bottom with active frame highlighting, locals list, and return value annotations.
4. **Unit Tests**:
   - Added tests in `tests/runtime.test.js` verifying function call jumping, hoisted declaration skipping, and call stack arguments/locals/returns inspection.

## Next Steps

- Asynchronous execution modeling: timers (`setTimeout`), Promises, Microtask Queue vs Task Queue.
- Scope chain visualization (Global scope vs Lexical/Closure scopes).
